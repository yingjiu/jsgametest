# 06 · HUD 与结算

平台在游戏画布之外，用**原生控件**画血条、比分和提示，并在结束时弹结算浮层。你只需返回数据。

---

## 1. `hud()` — 原生 HUD

每帧调用，返回：

```js
hud: function () {
  return {
    hp:     [1.0, 0.6],        // 血条：按【座位】索引，0~1
    scores: [12, 9],           // 比分：按【座位】索引，显示为 "12 : 9"
    tip:    "连击 x3 保持住！"  // 一行提示（可空）
  };
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `hp` | `float[]` | 长度 2，按座位索引，取值 `0~1`（平台画成两条血条）。不需要血条就填 `[1,1]` |
| `scores` | `int[]` | 长度 2，按座位索引，显示成 `A : B` |
| `tip` | string | 一行提示，`""` 表示不显示 |

**要点**：

- 数组**一律按座位索引**（`[0]` 是座位 0，`[1]` 是座位 1），**不要**按"我/对手"排——否则客人端会左右颠倒；
  平台在渲染时已按本机座位把"你/对手"标签映射好。
- 平台**每 200ms** 轮询一次 HUD，所以不必做高频动画（动画请画在 canvas 上）。
- **不要在 canvas 上重复画分数**：那是原生 HUD 的职责，重复画会出现两处分数，用户分不清哪个是自己的。
  画布上适合画"原生没有的"东西，如倒计时条、连击倍率、瞄准线。

---

## 2. `isFinished()` 与 `result()` — 结算

每帧检查 `isFinished()`，一旦为 `true` 就调一次 `result()`，平台弹出结算浮层：

```js
isFinished: function () { return this.t <= 0; },

result: function () {
  return {
    winner:  this.score[0] > this.score[1] ? 0
           : (this.score[1] > this.score[0] ? 1 : -1),   // -1 = 平局
    scores:  [this.score[0], this.score[1]],
    summary: "蓝 12 : 9 粉",                               // 一句话结果
    stats:   [["蓝方得分","12"], ["粉方最高连击","7"]]      // 若干 [名称, 数值] 行
  };
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `winner` | int | 获胜**座位号**；`-1` 表示平局 |
| `scores` | `int[]` | 最终比分（按座位），显示在结算页 |
| `summary` | string | 一句话总结（可空，空则平台兜底） |
| `stats` | `[string,string][]` | 明细行，值建议转成字符串 |

**注意**：

- `onOver` 只会被调用**一次**（SDK 内部有 `overSent` 去重）；
- 结束时**两端都会**判 `isFinished()`，但只有房主会额外把结算上报给对端；客人端本地也会显示同一结果。
- 「再来一局」由房主触发：对本游戏是**重新 boot**（会重新 `init`），不要依赖跨局残留状态。

---

## 3. 推荐分工

| 区域 | 谁画 |
|---|---|
| 血条、比分 `A:B`、一行提示 | **原生 HUD**（`hud()`） |
| 结算浮层、再来一局按钮 | **平台**（`result()`） |
| 倒计时条、连击数、瞄准线、准星、特效、场景 | **画布**（`render`） |

这样能保证视觉一致、且不用自己重写一套 UI。
