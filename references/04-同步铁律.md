# 04 · 同步铁律（违反必出双端不一致）

这五条是整套机制的地基。违反其中任何一条，症状都是「两端看到的不一样 / 分数对不上 / 一端卡住」。

---

## 1. 房主权威：逻辑只在房主端跑

- `tick(dt)`、`onInput(...)` **只会在房主端被调用**；
- `serialize()`（或 `state()`）**只在房主端被调用**，产出权威状态；
- `applyState(obj)` **只在客人端被调用**；
- `render()` **两端都调**，务必写成"只读状态、不改状态"。

```js
// ✅ 正确：推进逻辑只在 tick（仅房主会被调用）
tick: function (dt) { this.ball.x += this.vx * dt / 1000; },

// ❌ 错误：在 render 里推进物理 —— 客人端也会跑，两端各推一遍，直接漂移
render: function (now, ctx, c) { this.ball.x += this.vx / 60; /* … */ }
```

客人端**唯一合法**的本地计算是"纯视觉补间"（见 §6）与特效老化，它们不参与胜负。

---

## 2. 随机：一律 `ctx.rng()`

- 逻辑里**禁止** `Math.random()`；
- 用 `ctx.rng()` 或命名流 `ctx.rng("animals")`，种子由平台下发（`ctx.seed`），两端完全一致。

```js
// ✅
var ang = ctx.rng() * Math.PI * 2;

// ❌ 两端各随机一次 → 道具出生位置不同 → 立即不同步
var ang = Math.random() * Math.PI * 2;
```

**例外**：纯视觉抖动（屏幕震动、粒子抖动）不影响逻辑时可用 `Math.random()`，但**不能**参与位置/伤害/得分判定。
若特效要两端一致，就用 `ctx.rng()`（注意：混用会打乱随机序列的"对齐"，建议把逻辑随机与视觉随机分成两条流：
`ctx.rng.stream("fx")`）。

---

## 3. 时间：一律用 `tick` 的 `dt`

- 逻辑计时**禁止** `Date.now()` / `performance.now()`（两端时钟不同步）；
- 倒计时、冷却、生成间隔全部用 `dt` 累减：
  ```js
  tick: function (dt) { this.t -= dt; if (this.cool > 0) this.cool -= dt; }
  ```
- `render(now, …)` 的 `now` 只能用于**动画曲线**（如呼吸光、闪烁），不能影响胜负。

> 「一局时长」这类参数来自 `ctx.options`（房主配置、两端一致），配合 `dt` 累减即可。

---

## 4. 开始闸门：开跑前不要推进

平台先播「准备 / 1 / 开始！」倒计时，期间 `Arena.isStarted() === false`，**SDK 不会**调 `tick`/`onInput`，也不会判结算。
所以你只要在 `init(ctx)` 里把初始状态建好即可；想"开跑那一下"做点事就实现 `onStart(ctx)`。

**不要**在 `init` 里就开始倒计时 `this.t -= …`（那时还没跑，无所谓），但**不要**用 `performance.now()` 去自己算开局时刻。

---

## 5. 输入：只看 `a`，按座位处理

- `onInput(seat, x, y, a, id)` 的 `seat` 是**事件来源座位**，直接用它索引状态：`this.score[seat]++`；
- 判定类只处理 `a === 0`（其余是 MOVE/UP，会重复触发）；
- 乘客输入经网络到达房主，天然带一个 RTT；房主的输入本地即时生效。
  「谁先抢先得」由**到达房主的顺序**决定，无需额外处理。

---

## 6. 客人端的本地插值（强烈建议）

快照约 30Hz，客人若"收到就硬跳"，画面会一顿一顿。做法：`applyState` 里存**目标值**，`render` 里**指数逼近**。

```js
applyState: function (o) {
  // 存目标；位置跳变（重生/传送）时直接落点，避免补间出一条横穿全屏的假轨迹
  var prev = this.bx;
  this.tx = o[0]; this.ty = o[1];
  if (prev == null || Math.abs(this.tx - prev) > 0.25) { this.bx = this.tx; this.by = this.ty; }
},

render: function (now, ctx, c) {
  var dt = now - (this._last || now); this._last = now;
  if (dt > 100) dt = 100;
  if (!ctx.authoritative) {                      // 只有客人端补间
    var k = 1 - Math.exp(-dt / 45);              // 与帧率无关的指数逼近
    this.bx += (this.tx - this.bx) * k;
    this.by += (this.ty - this.by) * k;
  }
  /* 用 this.bx/this.by 画 */
}
```

用 `interp` cap 可以少写这段样板（见 `05` §3）。

---

## 7. 状态体积

`serialize()` 每帧（节流 30Hz）都会被打包跨桥下发。**只放"影响胜负或对端渲染"的最小字段**：

- 浮点用 `toFixed(3~4)` 或先乘后取整；
- 纯视觉粒子只同步最近的一小部分（示例 `neonstars` 里 `FX_SYNC_MAX = 14`），甚至让对端本地生成；
- 体积过大会堆在网络线程上 → 对端一卡一卡。
