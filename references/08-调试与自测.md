# 08 · 调试与自测

两层验证：**桌面浏览器**（秒级反馈，先在电脑上把玩法和渲染调顺）→ **两台真机**（验证联机同步）。

---

## 1. 桌面预览（无需安卓）

本 skill 自带一个通用预览壳：`scripts/preview/`，它用**打桩的 `Arena` 桥**模拟平台，加载真实 SDK 并 `boot()`，
所以你的游戏在浏览器里的行为与真机基本一致（房主权威模式）。
（下列路径均相对**本 skill 根目录**；`scripts/preview/dual-arena-sdk.js` 就是平台实际注入的权威源码。）

```
scripts/preview/
├── index.html              ← 预览页（含 mock Arena）
├── smoke-test.js           ← Node 冒烟测试
└── dual-arena-sdk.js       ← 平台注入的 SDK（权威源码）
```

### 用法

1. 把你的游戏脚本放到 `scripts/preview/` 目录（或改 `index.html` 顶部的 `PREVIEW.scripts` 指向相对路径），
   例如 `PREVIEW.scripts = ["game.js"]` 或 `["../../mygame/scene.js"]`。
2. 用本地服务器打开（**推荐**，这样能自动读取你的 `manifest.json`）：
   ```bash
   cd <skill根目录>/scripts/preview
   python -m http.server 8000
   # 浏览器打开 http://localhost:8000/
   ```
   直接双击 `index.html`（`file://`）也能跑，只是读不到 `manifest.json`，会退回 `PREVIEW.fallback` 配置。
3. 页面右上角有 **frames 计数**与 **日志面板**（`DualArena.log` / `console.*` / 未捕获异常都会显示），
   左上角是 HUD（来自你的 `hud()`），右下角是日志。若画面不动，先看日志里的 `boot ok …` / `frame err:`。

### 常用 URL 参数

| 参数 | 作用 |
|---|---|
| `?seat=1` | 以座位 1 预览（**分屏模式**下可看右半场的画面） |
| `?cross=1` | 强制分屏（`crossScreen=true`），用于对比两种模式 |
| `?aspect=1.6` | 改世界高度（模拟不同屏幕比例） |
| `?seed=123` | 改随机种子 |

> 预览壳是**单机**的：`pollRemoteState()` 恒为空，所以它验证的是「渲染 / 逻辑 / 手感 / 不崩」，
> **不验证**两端同步。同步必须上两台设备。

## 1.5 Node 冒烟测试（无需浏览器、无需安卓）

`scripts/preview/smoke-test.js` 用**打桩的 Arena 桥 + 打桩 canvas** 在 Node 里驱动真实 SDK，
把游戏 `boot` 起来跑若干帧并做断言。**秒级、可进 CI**，适合每改完一版就跑一次。

```bash
cd <skill根目录>/scripts/preview
node smoke-test.js ../../assets/template/game.js
node smoke-test.js ../../assets/examples/bowduel/game.js   # 多文件游戏会自动读它的 index.html 脚本列表
```

它会输出：

```
== 冒烟测试 ==
  game = ..\template\game.js
  caps = [clock,streams,ev]  cross=0  roundMs=30000
  scripts(自动发现) = ..\template\game.js
  ✓ 游戏对象已注册 (window.__DUAL_GAME__)
  ✓ DualArena.boot() 成功返回
  ✓ init 已执行（有 dot/ball 之类状态）
  ✓ 已回传 HUD (Arena.onHud)
  ✓ 房主已回传状态 (Arena.onState)
  ✓ HUD 结构合法 (hp/scores 长度 2)
  ✓ 注入输入后无异常且 HUD 合法
  ✓ 到达结束时上报结算 (Arena.onOver)
  ✓ 结算结构合法 (winner/scores)
  ✓ 全程无 frame err / init err
结果: 全部通过
```

- **退出码**：`0` 全部通过，`1` 有失败 → 可直接用于自动化。
- **自动取默认值**：会读游戏同级的 `manifest.json` 拿 `caps` / `crossScreen` / `roundMs`，一般**不用传参**。
- **可选参数**：`--caps=a,b`、`--crossScreen=1`、`--roundMs=3000`、`--aspect=1.6`、`--seed=123`。
- **多文件游戏**：自动解析 `index.html` 的 `<script src>` 按序加载。
- **能验证**：注册/`init`/`tick`/`onInput`/`serialize`/`hud`/结算链路、是否抛异常、HUD 结构是否合法。
- **不能验证**：两端联机同步、真机性能与手感 —— 那必须上两台设备（见 §2）与本机浏览器预览（见 §1）。

## 2. 真机联机自测

交给平台方集成后（把游戏文件夹放进 App 的 `assets/bundles/<id>/`），用两台设备一房主一客人实测：

1. 房主「创建房间」，客人扫码 / 输房间号加入；
2. 房主选你的游戏 → 点开始；
3. 观察：**倒计时结束后两端是否同刻开跑**、比分是否一致、断线重连是否正常。

### 看日志（唯一可靠的真机排障手段）

WebView 的 `console` 在真机上看不到，所以：

- 代码里用 **`DualArena.log("...")`**（SDK 会转到原生）；
- 电脑上执行：
  ```bash
  adb logcat -s duizhan
  ```
  `duizhan` 是应用的日志 tag。你会看到：
  - `boot ok v2 seat=0 auth=true aspect=2 …` —— SDK 启动成功、能力清单；
  - `js: <你的日志>` —— `DualArena.log` 的内容；
  - `frame err: …` / `init err: …` / `applyState err: …` —— 你的钩子抛异常（**这些不会崩 App，但会静默失效，务必盯**）。

### 确认设备上跑的是你最新那份

改了代码但没升 `manifest.version` → 设备上还是旧副本（见 `01` §5）：

```bash
adb shell run-as com.dual.arena cat files/bundles/<id>/manifest.json      # 看 version
adb shell run-as com.dual.arena grep -c "你新加的标识" files/bundles/<id>/game.js
```

## 3. 排障速查

| 症状 | 可能原因 |
|---|---|
| 页面全黑、无任何 log | `index.html` 没引用 `game.js`；或 `window.__DUAL_GAME__` 没注册（缺 `window.__DUAL_GAME__ = G`） |
| 有 `boot ok` 但画面不动 | `render` 里报错（日志有 `frame err:`）；或画到了画布外（没乘 `ctx.canvasW/H`） |
| 点击没反应 | 没判 `a === 0`，或画布没铺满/被别的元素盖住；分屏时点到的是本机看不到的对手半场 |
| 客人端画面一顿一顿 | `applyState` 硬跳，未做插值（见 `04` §6 / `05` §3） |
| 两端结果不一致 | 用了 `Math.random()` 或 `Date.now()` 参与逻辑；或在客人端改了状态 |
| 真机改动"没生效" | `manifest.version` 没 +1（见 `01` §5） |
| 帧率低 | 用了 `shadowBlur` / `filter`（见 `07` §2） |
