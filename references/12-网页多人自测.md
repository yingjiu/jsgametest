# 12 · 网页多人自测（无需真机互联）

目标：在**一个浏览器页面**里模拟 1~N 个「设备/座位」，本地验证多人同步、开局与手感，
免去「两台真机互联」的繁琐。

## 原理

`preview-multi.html` 是**父页面**，在一个网格里铺 N 个 `<iframe>`（每帧一个 `seat.html`）。
每个 iframe 内部跑一份**独立的** SDK + game.js 实例，用 `window.Arena` 桩桥与父页面通信：

- 每个座位捕获的触摸/鼠标 → 上报父页面；
- 父页面把**全部座位的输入**汇总后转给房主（seat 0）；
- 房主权威端跑 `tick`，`onState()` 把快照上报父页面；
- 父页面把房主快照**转发给每个客人**（seat ≠ 0）。

这正是真实架构（房主权威 + 中继转发）的本地等价物——逻辑判定只在房主发生，客人只
`applyState` + `render`，与真机完全一致。

## 用法

```bash
cd <skill根目录>/scripts/preview
python -m http.server 8000
# 浏览器打开：
http://localhost:8000/preview-multi.html?players=4
```

URL 参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `players` | 座位数 N（1~12） | 2 |
| `cross` | 是否分屏（每座位占一条竖带）；`0`=镜像（同屏共享） | 1 |
| `seed` | 随机种子（保证 N 座确定性一致） | 1357 |
| `scripts` | 游戏脚本路径（相对 preview 目录，逗号分隔） | game.js |

页面顶部可选人数 / 分屏，点「重载」即按新参数重建。左上为房主（HOST），其余为客人（GUEST）。

## 坐标模型（A1：多机竖带）

- `cross=1`：`seat i` 看到世界 `x ∈ [i, i+1]`，世界总宽 = N（2 人即左右半屏，是现状的特例）；
- `cross=0`：所有座位看到同一份世界 `x ∈ [0,1]`（用于单机多指 / 同屏多人）。
- SDK 的每座位坐标映射已是「按 `originX` 取本条竖带」，天然支持 N 座；游戏通过
  `ctx.players.length` 拿到总人数，HUD/结算数组按 N 个元素返回即可。

## 何时用它

- 验证多人：`serialize/applyState` 在 N 座间是否一致、`isFinished` 是否同刻结束、比分是否对齐；
- 验证开局：人数落在 `minPlayers..maxPlayers`、房主/客人 `ctx.players` 是否齐全；
- 手感联调：点不同 iframe 模拟多个玩家同时操作，观察房主快照在客人侧的还原。

> 单座细调仍用 `index.html`（`?seat=1` 看右半场、`?aspect`、`?seed`）。
