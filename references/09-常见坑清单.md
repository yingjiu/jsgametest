# 09 · 常见坑清单（症状 → 原因 → 正确做法）

按"踩坑频率"排序。每条都对应真实故障。

---

## 1. 两端不同步（最高频）

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 道具/敌人生成位置两端不同 | 逻辑用了 `Math.random()` | 用 `ctx.rng()` / `ctx.rng("name")` |
| 倒计时两端差很多、一端早结束 | 逻辑用了 `Date.now()`/`performance.now()` | 用 `tick(dt)` 累减 |
| 客人端画面越来越偏 | 在 `render` 里推进了物理（客人端也跑） | 推进只写在 `tick`；`render` 只读 |
| 随机"错位"导致后续全不同 | 某条随机流在一端多取/少取了一次 | 随机只在**两端都执行**的 `tick`/`init` 里取，别放 `render` |
| 一端分数多算 | 没判 `a`，把 MOVE 当点击 | 判定类只处理 `a === 0` |

---

## 2. 改了代码但"没变化"

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 重装 App / 重启手机，画面逻辑依旧旧版 | `manifest.version` 没 +1 | **改任何文件都把 `version` +1**（见 `01` §5） |
| 只改了 `name`/`description` 也不生效 | 同上 | 同上 |

---

## 3. 画面/交互问题

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 全黑没画面 | `#c` 没有尺寸（`clientWidth=0`） | 给 `#c` 设 `position:fixed;inset:0;width:100%;height:100%` |
| 画面偏小/模糊 | 自己乘了 dpr | 用 `ctx.canvasW/H`（已含 DPR，最高 2.5），别自己再乘 |
| 点击位置对不上 | 用 `clientX/Y` 直接当世界坐标 | 输入已由平台换算；自己接事件时用 `ctx.toWorld(px,py)` |
| 分屏时画到了屏幕外 | 没判可见性 | `if (!ctx.visible(x,y,r)) continue;` |
| 客人的按钮点了没反应 | 画布被其它 DOM 元素盖住 / 没设 `touch-action:none` | 让画布置顶且可接收指针事件 |
| HUD 左右颠倒 | `hud()` 里按"我/对手"排数组 | **一律按座位索引**：`[座位0, 座位1]` |

---

## 4. 性能

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 帧率低、画面"不流畅" | 用了 `shadowBlur` / `filter` | 用多层半透明同心圆或预渲染光晕（见 `07` §2） |
| 对端一卡一卡 | `serialize()` 太大 | 只发必要字段、浮点压缩、粒子限量（见 `07` §3） |
| 开局卡顿 | `init` 里做了重活 | 重活挪到 `onStart` 之后或分帧加载 |

---

## 5. 生命周期与 API

| 症状 | 原因 | 正确做法 |
|---|---|---|
| 倒计时还没结束就开跑 | —（平台已用开始闸门挡住） | 你不需要自己处理；只需实现 `onStart` |
| `DualArena.ev` 是 `undefined` | 没在 `caps` 里声明 `ev` | manifest 里声明 `caps:["ev", …]` |
| 结算只弹一次但我想跑动画 | `onOver` 只上报一次（设计如此） | 结算动画放 `render`/`result` 前的本地表现 |
| 再来一局后状态错乱 | 依赖了跨局全局变量 | 「再来一局」= 全新 `boot`，状态在 `init` 里重建 |
| 每帧 `hud()` 很重 | 平台 200ms 才轮询一次 | HUD 做轻量即可，动画画在 canvas |

---

## 6. preview 相关

| 症状 | 原因 | 正确做法 |
|---|---|---|
| preview 里读不到 `manifest.json` | 用了 `file://`（fetch 被拦） | 用 `python -m http.server` 起本地服务 |
| preview 里没有对手 | 预览是单机的 | 联机同步需两台真机 |
